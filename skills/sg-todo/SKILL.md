# SG 할 일 (SG Todo-List 커넥터)

㈜에스지솔루션 두 대표(정석진·김학미)의 할 일 원본은 SGCRM Firestore `todos`이고, 번호는 `T-0123`이다.
채팅에서는 **SG Todo-List 커넥터 도구**로 바로 읽고 쓴다. 저장 즉시 할 일 웹 화면(https://sggit-png.github.io/sg-todo/)과 SGCRM 「방금 바뀐 것」에 보인다.
**캘린더에 「할일」 일정을 만드는 옛 방법은 쓰지 않는다**(2026-10-09 커넥터로 교체).

## 세 칸 (2026-10-11부터)
할 일은 **시작일**로만 칸이 나뉜다.
| 칸 | 조건 | 보이는 것 |
|---|---|---|
| 🟠 **하고 있는 업무** | 시작일이 오늘이거나 지남 (완료 전) | `N일째` (시작한 날 = 1일째) |
| 🔵 **해야 할 업무** | 시작일이 앞날 | `D-n` — 그날이 되면 저절로 「하고 있는 업무」로 |
| 💡 **제안 업무** | `status: idea` — 업체와 소통하는 일이 아니라, 우리 회사가 먼저 제안해 볼 만한 아이디어 목록. 날짜는 말했을 때만, 와도 이 칸에 머묾 | `등록 N일 전` (빨간 표시 없음, 종료일 지나면 회색 「종료일 지남」) |
| ✅ **완료 업무** | 끝냄 | 끝낸 날 |
- 등록하면 **시작일 = 오늘**. 「내일부터」「다음 주 월요일부터」「10/20부터」라고 하면 `start`에 그 날짜.
- 긴급(★ `priority: high`)·기다리는 중(`status: waiting` + `waitingFor`)·마감(`due`, 선택)은 칸이 아니라 **꼬리표**다.
- 마감이 지났거나 14일째 넘게 끈 일은 빨간 표시(🔴) — `todo_list view=alert`.

| 도구 | 언제 |
|---|---|
| `todo_add` | 할 일 추가 → T-번호 |
| `todo_complete` | 완료(여러 개 가능). 끝낸 날은 `date`(어제·10/14 …, 기본 오늘). 반복이면 다음 회차가 자동 생성 |
| `todo_update` | 시작일·마감·내용·기업·메모·기다림 변경 |
| `todo_list` | 목록: open(기본 = 하고 있는+해야 할)·ing·todo·idea(제안)·all(+제안)·done·alert·waiting·week·trash |
| `todo_get` | 하나 자세히 + 변경 이력 |
| `todo_changes` | 언제 이후 바뀐 것 (since: `2026-10-08`, `3h`, `2d`) |
| `todo_delete` / `todo_restore` | 잘못 넣은 것 휴지통(30일) / 되살리기 |
| `company_find` | 기업 이름·사업자번호 찾기 |

커넥터가 연결돼 있지 않으면(도구가 없으면) "설정 → 커넥터 → SG Todo-List 를 연결해 주세요"라고 안내하고, 할 일 내용은 표로 정리만 해 둔다.
도구 설명에 보이는 view 목록이 위와 다르면(옛 목록이 남아 있는 경우) 위 목록의 값을 그대로 넣어 부른다 — 창구는 이미 받아 준다.

## 누가 하는지 (author) — 쓰기에는 꼭 필요
두 대표가 같은 Claude 계정을 쓴다. 쓰기 도구(add·complete·update·delete·restore)는 `author`(`정석진`·`김학미`·`공동`)를 반드시 넣는다.
1. 메시지가 `[정석진]` / `[김학미]`로 시작하면 그 사람.
2. 프로젝트 지침에 「나는 ○○○」이 있으면 그 사람.
3. 이 대화에서 앞서 밝힌 이름.
4. 그래도 모르면 **처음 쓰기 전에 한 번만** "정석진·김학미 중 누구세요?(두 분 공동이면 「공동」)"라고 묻고, 그 대화 동안 기억한다.
읽기(list·get·changes·company_find)는 묻지 않는다.

## 할 일인지, 있었던 일인지
- 앞으로 할 일("~해야 해", "다시 전화", "보내 줘야 함", "언제까지") → `todo_add`.
- 이미 끝난 일("통화했다", "보냈다") → 할 일이 아니다(업체카드 히스토리 몫). 그 일로 생긴 다음 일만 추가.
- 남이 해 주기를 기다리는 일("자료 준다고 함", "결과 기다림") → `status: waiting`, `waitingFor`에 누구·무엇. 다시 확인할 날을 말했으면 `due`에. 이미 있는 할 일이면 `todo_update`로 waiting. 기다림이 끝나면 `status: ing`.
- 끝났다는 소식("확인서 나왔다", "접수 완료", "T-0023 어제 끝냈어") → 해당 할 일을 찾아(`todo_list` query/company) `todo_complete`. **끝낸 날을 말하면 `date`에**(「어제」「그제」「10/14」 그대로). 말이 없으면 오늘. 이미 완료한 일의 날짜를 고쳐 달라면 같은 도구에 `date`만 다시. 어느 것인지 애매하면 후보 번호를 보여 주고 고르게 한다. 그 뒤 후속 할 일을 제안(아래).
- **제안거리**("하이퍼다인 ISO 인증 제안 예정", "○○에 연구소 설립 제안해 보자", "이 업체 벤처도 되겠는데") → `todo_add status: idea`. 업체가 아직 맡기지 않았고 우리가 먼저 꺼낼 일이다. **날짜는 사용자가 말했을 때만** — 「11/2부터」는 `start`, 「10/30까지」는 `due`(종료일). 말이 없으면 넣지 않는다(등록한 날로 채워지지 않음). 날짜를 붙이자고 먼저 권하지 않는다. 날짜가 있어도 제안 칸에 그대로 머물고(시작일이 와도 옮겨 가지 않음), 종료일이 지나도 빨간 표시 없이 회색 「종료일 지남」만 붙는다. 상담 중에 업체가 이미 해 달라고 한 일은 제안이 아니라 보통 할 일.
- 제안해서 **맡게 됨**("하이퍼다인 ISO 하기로 했어") → 그 제안 번호를 찾아(`todo_list view=idea company=…`) `todo_update status: ing`(오늘부터) 또는 `status: wait` + `start`(그 날부터 — `start`를 안 주면 제안에 적어 둔 시작일, 없으면 오늘). 새로 만들지 않는다 — 번호가 이어진다. 제안을 접으면 `status: cancel`.
- 미루기("다음 주로 미뤄") → `todo_update start=<새 시작일>` (해야 할 업무로 감). "지금 시작할게" → `start: 오늘`.
- 안 하기로 한 일 → 삭제가 아니라 `todo_update status: cancel`. 삭제(`todo_delete`)는 잘못 넣은 것·중복만.

## 넣는 법 (todo_add)
- `text`: 무엇을 하는지 분명하게("세무사 확인 결과 받기", "김태후 대표 재통화(중진공 접수 확정)"). 기업명은 text에 반복하지 말고 `company`에.
- `company`: 기업 이름(㈜·주식회사 빼도 됨) 또는 사업자번호. **후보가 여럿이라는 답이 오면** 후보를 보여 주고 고르게 한 뒤 사업자번호로 다시 부른다. 못 찾으면 기업 없이 넣을지 묻는다(새 업체면 sg-client-card로 등록 먼저).
- `start`: 시작일. **말이 없으면 넣지 않는다(= 오늘)**. 「내일부터」→`내일`, 「10/20부터」→`10/20`, 「다음 주 월요일부터」→ 날짜를 계산해 `2026-10-19`처럼. 제안 업무는 말했을 때만(말이 없어도 오늘로 채워지지 않음).
- `due`: 「~까지」라고 마감을 말했을 때만(`10/20`, `내일`, `+7`, `2026-10-20`). 시각은 text나 memo에. 그냥 날짜만 말하면(「10/20에 전화」) 그날부터 하는 일이므로 `start`에 넣는다. 제안 업무는 「~까지」를 말했을 때만 종료일로.
- `category`(업무 분야 — 화면이 칸 안을 이걸로 묶는다): **넣을 때마다 내용을 보고 하나 고른다.** policy 정책자금 · support 지원사업 · ven 벤처·이노비즈·메인비즈 · lab 기업부설연구소 · pat 특허·지재 · iso ISO 인증 · fund 일반자금조달 · confirm 확인서(공장등록·뿌리기업 등) · fin 재무·세무 · etc 기타·행정(일반 서류·견적·연락). 애매하면 etc. 비우면 「미분류」로 모인다.
- `kind`: call 전화 · doc 서류 · apply 신청 · visit 방문 · chase 독촉 · internal 내부 (분명할 때만). 급하다·중요하다고 하면 `priority: high`(긴급 ★).
- 매주·매달 하는 일이면 `repeat`(예: 매달 25일 → `{every:"month", day:25}`).
- 여러 건이면 표로 묶어 한 번에 확인받고 넣는다: `☎️ 청림테크 · 김태후 대표 재통화 · 10/8(목)부터` → "이렇게 넣을까요?" 사용자가 "바로 넣어"라고 했거나 분명한 한 건이면 바로 넣는다.
- 넣은 뒤 도구가 돌려준 한 줄(`T-0124 저장됨 · …`)을 그대로 보여 준다. 같은 내용을 2분 안에 다시 넣으면 창구가 새로 만들지 않는다.

## 조회
- "오늘 할 일"·"할 일 보여줘" → `todo_list`(open). "하고 있는 거" → ing, "해야 할 거"·"앞으로 할 거" → todo, "끝낸 거" → done, "급한 거·놓친 거" → alert, "기다리는 거" → waiting, "이번 주 마감" → week, "제안할 거·제안거리" → idea, "○○ 할 일" → company + view=all(제안까지).
- 결과는 도구가 준 줄을 그대로 쓰되, 많으면 긴급·빨간 표시를 먼저 요약한다. 번호(T-…)는 꼭 남긴다(다음 지시에 씀).
- "어제 이후 뭐 바뀌었어?" → `todo_changes`.

## 작업 중에 지켜보기
대화 중에 신청·제출, 실사 일정, 보완 요청, 결과 통보, 다시 연락할 약속이 나오면 답변 끝에 한 줄로 제안한다.
`📌 할 일로 넣을까요? 하이퍼다인 · 벤처 실사 준비 · 10/13부터 (마감 10/15)`
제안거리는 날짜 없이: `💡 제안으로 넣을까요? 하이퍼다인 · ISO 인증 제안`
이미 있는 할 일과 관련되면(같은 기업 열린 할 일) 새로 넣기보다 완료·수정을 제안한다. 무시하면 다시 묻지 않는다.

## 완료 뒤 후속 할 일 (제안만)
- 벤처확인 발급 → 자금·지원사업 재검토 (갱신 알림은 자동 할 일이 만든다)
- 연구소·전담부서 설립 → 연간신고는 자동 생성
- 특허 가출원 → 12개월 안에 정규출원 전환
- 정책자금 접수 → 결과 확인(약 2~4주 뒤), 불승인이면 사유 확인
- 견적·제안 발송 → 5영업일 뒤 후속 연락
(인증 갱신 D-90·ISO 차기심사·연구소 연간신고는 매일 06:00 자동으로 생기니 따로 넣지 않는다)

## 업체카드(sg-client-card)와 함께
- 업체 작업을 시작하면 `todo_list view=all company=<업체>`로 열린 할 일과 💡 제안거리를 함께 보여 준다(「이 업체에 제안할 것: ISO 인증」).
- "○○ 정리하자": 카드를 갱신하기 전에 이 대화에서 생긴 할 일·끝난 일을 표로 묶어 확인받고, 추가는 `todo_add`, 끝난 것은 `todo_complete`로 처리한다.
- 카드의 「다음 할 일」에는 가장 급한 2~3건을 T-번호와 함께 적고 "전체는 할 일 프로그램"이라고 적는다.

## 하지 않는 것
- 고객 개인정보(주민번호, 계좌번호 등)를 할 일 내용·메모에 적지 않는다.
- 미팅·실사 약속 같은 보통 일정은 Google Calendar에 일정으로 만든다. 약속을 할 일로 바꾸지 않는다(준비할 일이 있으면 그것만 할 일로).
- 사용자가 확인하지 않은 여러 건을 한꺼번에 완료·삭제하지 않는다.
